# 保存后继续运行

主对话保留每轮的运行状态、事件、计划与结果。关闭浏览器页签只断开查看，不会取消服务器任务。服务退出或重启会将未完成运行标为 `interrupted`，保留已保存的事件和结果，不自动重放工具。

失败、中断或手动停止后，在当前线程最新运行的状态栏点 **从已保存上下文继续**。服务器保存一条后续请求，包含原目标、上一轮已记录的成功工具摘要、计划、部分输出和审批状态，然后创建关联的新运行。旧运行保留原状态；新运行显示来源，可打开 **查看原运行**，也可通过 **已保存的运行** 浏览过去的事件与部分输出。查看日志不调用模型或工具。刷新后会定位到最新保存的消息。

继续使用当前线程配置和仍可用的显式资源。已完成操作不会由系统自动重放；状态不明的外部写入仍可能已经发生，需要先核对结果。旧运行中的审批不延续，新动作仍需各自授权。这是根据保存状态建立新一轮，不是恢复上一进程的执行栈或承诺外部操作 exactly-once。

## API 与持久记录

`POST /api/runs/:id/continue` 接收 `{workspaceId, threadId, requestId}`，沿用现有登录、Origin、CSRF 和工作区校验。仅最新的终止主运行可继续，运行中的任务和独立子任务不可通过此入口继续。请求不得附带替换目标、工具、命令或模型参数。

相同原运行与 `requestId` 派生确定性消息 ID；即使工作区消息已经提交、进程却在新运行入队前退出，重试仍复用该消息。新运行在现有私有 run 数据库的 request 元数据保存来源，公开信息返回 `continuedFromRunId`。重复请求返回同一运行。工作区写入继续使用现有 `If-Match` 版本机制，新字段不要求迁移账号或重建数据库。

服务器生成的续接消息标记为 `runContinuation`；分身记忆的原话整理排除这些摘要，服务端也拒绝把它们当作真人原话证据。

DCU 作业的有效期在聊天页显示。作业到期后消息、运行日志和产物仍保存在本地工作区；接上新的有效作业，再显式继续。截止时间不会触发自动续租。

## 验证

```sh
node --test --test-isolation=none server/run-continuation.test.mjs server/agent-runs.test.mjs server/run-client.test.mjs
node scripts/verify-run-continuation-ui.mjs
npm run typecheck
```

测试使用临时 SQLite、真实 HTTP/会话/CSRF、服务关闭重启与受控模型响应。覆盖幂等、源信息不变、工作区隔离、跨数据库提交边界、已批准本地副作用不重放、旧审批不能授权新动作。浏览器验收通过真实界面发起继续并读取原日志，无 API 拦截。它不代表生产模型自主完成质量验收。
