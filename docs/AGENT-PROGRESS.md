# Agent 当前进度与任务演练

2026-11-12。本轮面向 `npm run dev` 的 SQLite `/api/runs` 主对话运行层；`dev:v1`、PostgreSQL 和 Rust 是独立入口，历史报告不能证明它们是当前部署。

| 能力 | 当前行为 | 本轮验证 |
| --- | --- | --- |
| 后台任务 | 持久化运行与事件；刷新/关闭查看页面不取消工作；重启不会自动重放命令 | 运行层回归 |
| 任务拆分 | 可调用真实保存的 agent，创建隔离子对话；两个子执行槽；最多八个直接子任务 | 两个只读子 agent 各读取保存的简报、回收不同结论 |
| 权限 | 子任务只有父任务和目标 agent 的只读权限交集，不能 Shell、改文件、创建产物或再次委派 | 权限、伪造、跨工作区与预算回归 |
| 计划与依赖 | `dependsOn` 校验依赖、环和推进顺序；`childRunId` 关联真实子任务，成功保存结果后才可标完成；后续更新不能抹去已有依赖/结果关联 | 单元和运行层验收 |
| 汇总与交付 | 主 agent 汇总实际结果后准备 Document，主运行成功时由服务器保存 | 验收文档含实际来源、95/15/35 数量及未到货假设 |
| 失败与取消 | 父任务提前结束判失败；取消/失败连带结束未完成子任务 | 实际取消与回归；不会留下孤儿任务 |
| Shell/技能/文件 | 既有管理工具经过具体动作审批；不能因计划或子任务文本扩大权限 | 既有回归继续保留 |
| 模型可靠性 | 连接成功与多步任务成功分别验收；SCNet 保留原目标、纠正与真实子结果 | 真实模型记录单列，不能用 fixture 推定 |

具体演练是：根据仓储简报（现货75件，预计到货20件但未核实，需求110件），将数量核算和履约风险拆给两个子 agent，等两份结果后生成建议。预期到货落实时可交95件、缺15件；未到货时缺35件。全部输入均为演练资料，不读取原用户仓储数据。

运行与证据见[拆分执行验收](verification-decomposition/README.md)。普通 HTTP fixture 演练通过八项检查，真实认证、授权、文档读取、子任务调度、持久事件、保存、取消与服务重开均经过实际代码。模型选择和输出为受控 fixture，这证明具体运行机制，不代表真实模型已达到自主拆分质量。

SCNet 上下文修复保留原目标和最新纠正，子任务完成事件仅作为观察；保留真实子运行 ID、结果状态、正文片段、agent 名单及计划依赖。大文本仍受窗口限制。既有的1.5B重复搜索记录保留，新任务另外记录，不覆盖历史失败。
