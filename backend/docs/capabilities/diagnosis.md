# 失败诊断与恢复

`GET tasks/:id/overview` 从任务错误码、模型尝试、操作日志和验收历史返回 `diagnosis`，包含 category、stage、code、message、lastOperation、issues；`budget` 返回根任务树累计活动时间、调用、token、预留 token、传输和产物字节。

分类为模型请求、工具执行、能力缺失、预算、交付验收、不确定副作用及运行时错误。没有真实错误记录时返回 `null`。程序 stdout/stderr 继续在活动面板展示；模型私有推理、凭据和原始服务端异常不公开。Rust 将模型失败的安全错误码同时记录到 model_attempts；无法准确归类的异常保留运行时错误，不能虚构原因。

服务端 `availableActions` 返回 `pause`、`resume`、`retry`、`provide_input`、`cancel`、`new_task` 的合法子集。前端直接使用这个集合，不再根据自定义错误白名单猜测。请求时服务端仍检查最新状态；按钮不是执行授权凭证。

失败任务的重试沿用原任务、检查点和预算。预算或验证失败、预算实际已耗尽、根树有未确定副作用时，不提供或接受重试。`uncertain` 允许检查文件、取消或新建后续任务，不自动复做。终结任务不能靠 resume 复活；补充信息只对仍可继续的任务开放。

限制：诊断不自动修复账户配额、安装能力或执行第三方动作。新建后续任务是用户通过现有对话入口发起的新任务，不重置原任务的账本，也不自动重放原操作。

验收包括预算错误以及“错误码可重试但实际预算已经用尽”的拒绝、不确定操作、跨工作区 404、CSRF 拒绝和失败后已保存文件可下载。
