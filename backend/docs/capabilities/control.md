# 暂停与继续

用途：暂时停止整个任务树的新工作，同时保留检查点、预算、文件和待处理输入。

- `POST /api/v1/tasks/:id/pause`：解析到所属根任务并持久记录 `pause_requested`；没有在途操作时立即成为 `paused`。
- `POST /api/v1/tasks/:id/resume`：根控制恢复 `normal`；响应为根任务完整概览。
- 重复同方向请求不重复修改控制修订号。已经终结时返回最终状态，不重新启动。取消仍走原接口并立即撤销租约。

控制字段与任务 `state` 独立。排队任务、等待子任务、用户、审批、浏览器人工接管、计时器的条件均保留。正在运行的 TS 片段在安全边界释放租约并回到可调度状态；控制字段阻止领取。Rust 在片段结束释放租约，模型响应和 outbox 持久化后停止后续派发。原生同步工具遇到暂停时丢弃尚未提交的私有片段，用持久模型响应恢复，不重做已提交操作。

API 控制、领取、模型预留、模型桥接、应用工具、委派和实际浏览器派发在同一短事务控制锁下决定准入。收到暂停请求前已准入的操作保留原有超时，可以完成并保存；暂停不主动杀死模型、计算或网站操作。浏览器待派发 outbox 可以留在队列；已派发浏览器操作必须保存结果后才算暂停完成。异步结果与人工交还仍可落库、解除其自身等待条件，不能解除任务暂停。

暂停期间追加指令会保存。用户回答可以解除 `waiting_user`，但不会解除暂停；审批未解决时保持审批等待，浏览器未交还时保持浏览器等待。现有审批接口只记录决定，外部动作执行器仍不可用。继续不补发或伪造审批。

重启后领取路径先恢复过期租约并结算预算，再检查持久暂停意图。未知计算或网站副作用保持 `uncertain`，不自动重放；安全工具使用原 operation ID，文件保存沿用原 operation key。预算按活动片段计费，暂停等待不增加活动毫秒，也不重置模型调用、token 或文件预算。

完成／取消竞态以事务提交结果为准：完成可以赢过暂停；取消之后的回调不得重启任务。暂停与立即继续交错时，被暂停拒绝的片段会释放租约重新排队，不等待租约过期。

验收：隔离数据库覆盖 TS/Rust 的排队、模型、计算、浏览器回调、子任务树、追加指令、审批、取消、原生委派及重启；另有真实模型、真实沙箱和 UI 记录。每种外部网站的全部副作用窗口仍需站点专门验收。
